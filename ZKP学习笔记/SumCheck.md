# Sum-Check Protocol



## Start

该协议的目标是让**证明者**向**验证者**证明某个数字 $H$ 是一个多项式 $g(x_1,\ldots,x_n)$ 的所有评估值的总和

>在本文中，我们将使用布尔超立方体上的评估，这意味着变量只能是0或1

Example: 对于一个多项式$g(x_0,x_1,x_2)=2{x_0}^3+x_1+x_0x_2$，证明者可以轻松计算：
$$
\begin{align*}H := &g(0,0,0) + g(0,0,1) + g(0,1,1) + g(1,1,1) + g(1,1,0) + g(1,0,0) + g(1,0,1) + g(0,1,0)\\
H := &0 + 0 + 1 + 4 + 3 + 2 + 3 + 1\\
H := &14
\end{align*}
$$
**此处证明者的目标是让验证者相信 $H$ 已被正确计算，而无需验证者自行计算！**

## 只需证明

协议的第一步是证明者向验证者发送一个多项式 $g_0$。**它是一个单变量多项式**，定义如下：
$$
g_0(x_0)=g(x_0,0,0)+g(x_0,1,0)+g(x_0,0,1)+g(x_0,1,1)
$$
你可以看到它与初始和非常相似，但仅限于变量$x_0$变化，而其他变量$x_1$和 $x_2$ 在所有可能值（0 或 1）上求和。

这个多项式很有用，因为如果验证者确信多项式是正确形成的，他可以通过自己计算$H$来得到：
$$
H:=g_0(0)+g_0(1)
$$
如何能让验证者确信$g_0$格式正确？为此，我们可以利用 Schwartz-Zippel 引理

验证者会随机采样一个$r_0\in \mathbb{F}$，他只需要检查
$$
g_0(r_0)=g(r_0,0,0)+g(r_0,1,0)+g(r_0,0,1)+g(r_0,1,1)
$$
如果这个有效，那么多项式就是正确形成的

我们仍然存在一个问题，因为验证者计算右侧（RHS）的成本仍然很高（计算整个总和需要进行$2^3$次评估，而右侧需要$2^2$次，所以只减少了一半的工作量）。

为了解决这个问题，我们首先注意到$g_0(r_0)$实际上是一个值，我们称他为$H_1$，例如。所以现在我们有：
$$
H_1=g(r_0,0,0)+g(r_0,1,0)+g(r_0,0,1)+g(r_0,1,1)
$$
或许你已经意识到了，但这实际上是调用和检验协议的完美场景！其核心思路是递归地应用该协议，直到最后一步，此时验证者只需用随机值调用一次$g$，就能确保之前所有步骤都是正确的！



Example:

让我们以我们想要证明的初始求和检查实例 $H=14$和
$$
g(x_0,x_1,x_2)=2x_0^3+x_1+x_0x_2
$$
为例

1. 证明者向验证者发送 $g_0=8x^3+2x+2$

>$$
>\begin{align*}
>g_0&=g(x_0,0,0)+g(x_0,1,0)+g(x_0,0,1)+g(x_0,1,1)\\
>&=2x^3+2x^3+1+2x^3+x+2x^3+1+x\\
>&=8x^3+2x+2
>\end{align*}
>$$

2. 验证者确保$g_0(0)+g_0(1)=H$ 然后随机采样一个$r_0=12$并计算$g_0(12)=13850$ 

3. 证明者召唤一个新的求和检查实例，他想要证明 
   $$
   13850=g(12,0,0)+g(12,0,1)+g(12,1,0)+g(12,1,1)
   $$

4. 证明者发送 $g_1=6924+2x$

>$$
>\begin{align*}
>g_1&=g(12,x_1,0)+g(12,x_1,1)\\
>&=3456+x+3456+x+12\\
>&=6924+2x
>\end{align*}
>$$

2. 验证者确保 $g_1(0)+g_1(1)=g_0(r_0)=g_0(12)=13850$，然后随机采样 $r_1=5$ 并计算 $g_1(r_1)=6934$

3. 证明者召唤一个新的求和检查实例，他想要证明 $6934=g(12,5,0)+g(12,5,1)$

4. 证明者发送 $g_2=3461+12x$

>$$
>\begin{align*}
>g_2&=g(12,5,x_2)\\
>&=3456+5+12x\\
>&=3461+12x
>\end{align*}
>$$

2. 验证者确保 $g_2(0)+g_2(1)=g_1(r_1)=g_1(5)=6934$，然后随机采样 $r_2=2$ 并执行最终检查，其中他评估 $g$ 并验证 $g_2(r_2)=g(12,5,2)=3485$，如果这是真的，那么求和检查协议是有效的！

>验证者确保 $g_2(0)+g_2(1)=g_1(r_1)$，然后随机采样 $r_2=2$ 并执行最终检查，其中他评估 $g$ 并验证 $g_2(r_2)=g(12,5,2)$，如果这是真的，那么求和检查协议是有效的！
